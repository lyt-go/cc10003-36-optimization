# 洞察调度：去重与续发设计说明

## 1. 业务入口与共享版本

以「洞察推送（insight）」为唯一业务入口。一次报告生成会产出一个**报表产物**，并同时确定三个版本，
洞察报告、报表产物、渠道回执三者共享同一个「生成版本」：

| 版本字段 | 含义 | 递增时机 |
| --- | --- | --- |
| 产物版本 `v1/v2/...` | 报表产物（推送给渠道的实际内容） | 每次生成产物都递增 |
| 报告版本 `r1/r2/...` | 洞察报告内容版本 | 仅报告内容变更时递增（可只换产物不换报告） |
| 生成版本 | = 产物版本，贯穿报告、产物、回执 | 随产物版本 |

`GET /api/insight/{id}/dispatch` 返回「版本一致」校验：报告上的生成版本/报告版本必须与当前产物完全相同。

## 2. 去重边界：四元组唯一回执

一条渠道回执由下面四个字段唯一识别（`app/dispatch/models.py: dedup_key`）：

```
（产物版本, 报告版本, 渠道, 接收范围）
```

- 一个四元组在生效期内**只有一条回执**；分段发送结果挂在该回执的「分段明细」里，
  因此分段查看天然不会重复显示同一条，分页再做一次基于四元组的防御性去重。
- 不同接收范围是不同四元组，各自独立一条回执，互不影响续发。
- 换版后版本号变化，新旧回执四元组天然不同，可共存而不冲突。

## 3. 重试边界：成功复用、失败只补缺口

- **命中复用**：四元组已存在「成功」回执时，直接复用，不调用渠道网关，命中计数 +1。
- **缺口续发**：未成功的回执只对「待补发」分段调用网关，已送达分段（含回执号）原样保留，
  补发按分段计数。`POST /{id}/retry` 在循环外层就跳过成功键，连键锁和网关都不进入。
- **部分完成**：一个渠道超时、另一个成功时，报告停在「部分完成」并列出「待补渠道」，
  不会整体标失败后重发全部。只有当没有任何渠道拿到送达分段时才标「全部失败」。
- 每个渠道都有可见结果与失败原因；超时与错误的区别保留在回执「渠道结论」与分段「失败原因」里。

## 4. 并发互斥：每四元组一把锁 + 进行中标记

- 每个四元组一把 `threading.Lock`，另有全局 `_in_progress` 集合。
- 检查标记与置位在同一把键锁内原子完成；发送期间释放键锁，使并发的其他调度任务能观察到
  进行中标记，记一次「冲突」并跳过，而不是排队等锁后重复发送。
- 压测结论：8 个任务并发处理同一报告的 4 个四元组，最终每个四元组恰好一条回执、
  分段发送总数严格等于 `四元组数 × 分段数`，其余全部计为冲突。
- 共享列表（回执/产物/执行记录）的读写都在元锁 `_meta_lock` 下做快照或变更，
  网关 I/O 在锁外执行，避免持锁等待渠道。

## 5. 空回执与换版失效

- **空回执不落地**：渠道一轮没有任何回执内容时，不写回执、不计成功；该渠道组合登记进
  「期望组合」台账，仍会出现在报告的待补渠道里，并在执行记录中留痕，后续恢复可正常补发。
- **产物换版**：旧产物版本下仍生效的回执整体置为「已失效」（`生效=false, 历史=true`），
  每条计入「失效」；默认回执列表不返回，带 `include_history=true` 可查，
  绝不参与新版本的推送状态统计。

## 6. 四类验收计数

每次推送/续发/换版都写一条执行记录，统一给出：命中、补发、冲突、失效。
报告详情接口返回跨执行记录的累计计数，前端在调度详情弹窗中展示。

## 7. 模块与接口

- `app/dispatch/models.py`：状态常量、四元组键、可变计数器
- `app/dispatch/gateway.py`：渠道网关模拟（成功/超时/错误/空回执，支持单次编排与固定结果）
- `app/dispatch/engine.py`：线程安全调度引擎（产物、回执、执行记录、去重续发）
- 接口前缀 `/api/insight`：`/{id}/artifact`、`/{id}/push`、`/{id}/retry`、
  `/{id}/dispatch`、`/{id}/receipts`、`/{id}/runs`、`/dispatch/demo`、`/dispatch/reset`

## 8. 续发样例（对应需求 INSI-0003）

1. `POST /api/insight/dispatch/demo`：邮件成功、短信超时 → 报告「部分完成」，待补 `短信/默认接收范围`；
2. `POST /api/insight/3/retry`（短信恢复成功）：邮件命中复用、短信只补 3 个缺口分段 → 「全部完成」；
3. `POST /api/insight/3/artifact`（换版）：旧邮件/短信回执全部「已失效」仅作历史，新版本推送状态从零开始。
